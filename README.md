# 다비봇 AIrobot · 로봇팔 AI 융합 실습실

[![Deploy to Netlify](https://www.netlify.com/img/deploy/button.svg)](https://app.netlify.com/start/deploy?repository=https://github.com/gim6110-glitch/AIrobot)


본 프로젝트는 EEZYbotARM Mk2를 바탕으로 고등학생이 로봇팔을 만들고 제어하며, AI가 인식한 결과를 검증하고 집게를 개선하는 실습을 지원합니다.

**검증 상태:** 소프트웨어 시제품. 실제 Arduino·서보·EEZYbotARM Mk2 실물에 대한 동작 검증은 아직 실시하지 않았습니다. 시뮬레이터는 개념적 2D 그림이며 실제 로봇의 역기구학, 충돌, 모터 토크를 계산하지 않습니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 웹 시뮬레이터 | A 원·B 삼각형·C 십자 → 보관함의 집기 흐름을 시각화 |
| 한국어 채팅 | 규칙 기반 해석(LLM이 아님) 또는 Netlify LLM 함수로 한국어 명령 분석 |
| 사진 분류 | 웹캠 3등분 영역 + 사용자가 학습한 Teachable Machine 모델 |
| 물리적 제어 | Chrome/Edge 데스크톱 Web Serial → USB Arduino UNO R3 |
| 서보 구동 | UNO I²C → PCA9685 → 베이스·어깨·팔꿈치·집게 4개 서보 |
| 보정·승인 | 9개 자세 저장, 제한 각도, 사람이 대상·주변 안전 확인, STOP, 실행 기록 |


## 0. 가장 쉬운 첫 연결 — 계산 대신 화면에서 선택

**사전 준비:** EEZYbotARM Mk2 조립, 서보와 PCA9685 배선, 별도 전원, Arduino 펌웨어 업로드, 하드웨어 차단 스위치가 필요합니다. USB로 연결한다고 펌웨어나 서보 배선이 자동 설치되지는 않습니다.

1. PC의 Chrome/Edge에서 배포된 웹사이트를 열고 **USB 연결 · 자동 인식 시작**을 누릅니다.
2. 이전에 포트 권한을 허용했다면 허용된 포트를 재사용합니다. 처음이면 Arduino USB 포트를 선택합니다. **READY AIROBOT/1** 응답을 받은 경우에만 프로그램이 호환 장치로 인식합니다. 연결만으로 모터가 움직이지는 않습니다.
3. **카메라로 작업대 거리 자동 계산**에서 웹캠을 켜고 A4 종이를 가로(297×210mm)로 놓은 작업대를 촬영합니다. 화면 안내에 따라 **A4 네 모서리 → 로봇 베이스 → 로봇의 정면 → A/B/C/보관함 중앙** 순서로 10곳을 클릭합니다. 사용자가 거리 계산을 직접 할 필요는 없습니다.
4. 프로그램은 평면 X·Y(mm), 로봇 베이스에서 물체까지 거리, EEZYbotARM Mk2 참고 운동학 모델의 도달 가능성을 표시합니다. **이 결과는 실제 관절에 전달하지 않습니다.** 카메라가 깊이(z)·물체 높이·집게 접촉력·서보 방향을 측정하지 못하기 때문입니다.
5. 최초 모터 작동 시 팔을 받침대에 지지한 상태에서 **축별 안전 점검 → 선택한 축만 시험**을 사용해 한 축씩 확인하세요. 축별 점검용 `AXIS,축번호,각도`는 한 번에 선택한 서보만 갱신하지만, 그 서보의 **최초 출력 때는 현재 축 위치에서 갑자기 움직일 위험**이 있습니다. 그다음 **9개 고정 자세**를 확인하고 저장합니다. 각 자세는 **관절 각도 전송 → 실물 동작 확인 → 현재 각도 저장** 순서로 진행합니다. 실제 동작 확인 전에는 보정 저장이 막힙니다.
6. 이후 동일한 로봇/작업대/브라우저에서 포트 연결 → 작업대 표식 확인 → 사람 승인 후 채팅 집기를 실행할 수 있습니다. 로봇의 부품, 서보, 카메라 위치가 바뀌었다면 반드시 다시 보정해야 합니다.

### 왜 연결만으로 바로 움직이지 않나요?

컴퓨터가 USB 장치에서 알 수 있는 것은 장치 종류와 펌웨어 응답 정도입니다. **서보 축에 어떤 방향으로 링크가 부착되었는지, 물리적 회전 제한이 어디인지, 카메라에 보이는 픽셀의 실제 깊이, 현재 집게가 물체에 닿는지**는 USB 통신만으로 알 수 없습니다. 잘못된 각도를 임의로 보내면 로봇이 스스로 충돌하거나 부품이 손상될 수 있습니다. 이에 자동 위치 계산은 참고/설계용으로 제공하고, 실제 집기는 검증된 자세에서만 허용합니다.

이 프로젝트가 사용하는 참고 기구학 치수는 L1=92mm, L2=135mm, L3=147mm, L4=87mm입니다. [easyEEZYbotARM Mk2](https://github.com/meisben/easyEEZYbotARM)의 실험적 참고치이며 실제 인쇄 치수·서보 연결 방향을 보증하지 않습니다. 참고 코드와 학습자료는 원저작권과 라이선스를 확인해 사용하세요.

## 1. Netlify 배포

1. Netlify의 Add new project → Import an existing project → GitHub를 선택합니다.
2. gim6110-glitch/AIrobot 저장소, main 브랜치를 선택합니다.
3. Build command는 **비워 둡니다**. Publish directory는 **.**, Functions directory는 **netlify/functions**입니다. netlify.toml에 설정되어 있습니다.
4. 배포된 HTTPS 주소를 데스크톱 Chrome 또는 Edge에서 열면 시뮬레이터를 사용할 수 있습니다.

**Netlify 사이트가 실제 로봇을 인터넷으로 원격 제어하는 것은 아닙니다.** 실제 Arduino가 USB로 연결된 **그 컴퓨터**의 Chrome/Edge에서 Netlify 페이지를 열어야 Web Serial로 구동할 수 있습니다. 휴대폰·Safari·Firefox에서는 Web Serial 연결이 불가능하거나 제한적일 수 있습니다.

### LLM 채팅 연결 (선택)

Netlify → Site configuration → Environment variables에서 다음 환경변수를 지정하고 다시 배포하세요.

| 변수 | 값 |
|---|---|
| LLM_API_KEY | 사용하는 LLM 제공자에게 발급받은 개인 키 (GitHub에 절대 업로드하지 않음) |
| LLM_BASE_URL | 제공자 OpenAI 호환 API의 HTTPS 기본 주소 (예: https://api.openai.com/v1) |
| LLM_MODEL | 제공자에서 사용 가능한 모델 ID (Qwen 계열 지원 시 해당 모델 사용 가능) |

웹에서 **Netlify LLM 연결**을 선택하면 입력 문장을 서버가 분류해 ‘대상, 출발 위치, 보관함’ JSON을 반환합니다. **LLM은 서보 각도를 생성하거나 자동으로 실행시키지 않습니다.** 입력이 모호하면 보류합니다. 모델을 설정하지 않은 상태에서는 ‘규칙 기반 체험 (AI 모델 아님)’을 사용하세요.

사용자 컴퓨터에서 실행하는 Ollama는 Netlify 서버가 자동으로 접근할 수 없습니다. 별도 로컬 브리지가 없으므로 이 버전은 OpenAI 호환 클라우드 API를 사용합니다.

## 2. Arduino UNO R3 · PCA9685 예시 배선

실제 부품의 허용 전압, 전류, 커넥터 표기를 우선 확인하세요. 아래는 **예시**입니다.

| Arduino UNO R3 | PCA9685 | 의미 |
|---|---|---|
| 5V | VCC | 제어 보드 논리 전원 |
| GND | GND | 제어 보드 및 외부 서보 전원의 공통 GND |
| A4 | SDA | I²C 데이터 |
| A5 | SCL | I²C 클록 |

PCA9685의 **V+**에는 서보모터 정격에 맞는 **별도 5V 전원**을 연결합니다(예: 5V/10A급, 실제 부하 확인 필요). 외부 전원(-)과 Arduino GND를 공통 연결하세요. **Arduino 5V 핀으로 MG995 여러 개를 구동하면 안 됩니다.** 모터 전류를 일반 브레드보드 신호선에 분배하지 말고 적절한 전원 단자, 배선, 퓨즈, 물리적 전원 차단을 마련하세요.

| PCA9685 채널 | 기능 | 예시 서보 |
|---|---|---|
| 0 | 베이스 | MG995 |
| 1 | 어깨 | MG995 |
| 2 | 팔꿈치 | MG995 |
| 3 | 집게 | SG90 |

**중요:** 실제 관절 방향/서보 펄스값이 다를 수 있습니다. 펌웨어의 CHANNELS, MIN_US, MAX_US, MIN_DEG, MAX_DEG, REVERSE, BOOT_DEG를 각 로봇팔에 맞게 점검해야 합니다. 기본 펄스와 각도는 제작물에서 확인한 보정값이 아닙니다.

### Arduino 펌웨어 업로드

1. Arduino IDE에서 Arduino Uno R3 보드와 COM/USB 포트를 선택합니다.
2. 라이브러리 관리자에서 Adafruit PWM Servo Driver Library 및 Adafruit BusIO를 설치합니다.
3. arduino/AIrobot_PCA9685/AIrobot_PCA9685.ino 파일을 엽니다.
4. 펌웨어의 핀·펄스·제한 각도·서보 방향을 확인하고, 서보 별도 전원을 끈 상태에서 업로드합니다.
5. 115200 baud 시리얼 모니터에서 HELLO → READY AIROBOT/1로 통신을 확인한 뒤 시리얼 모니터를 닫습니다.
6. 별도의 물리적 차단·지지대를 준비한 뒤 **부하 없이** 작은 각도로 한 관절씩 점검합니다. 초기 각도 90°가 실제 장치의 안전한 자세라는 보장은 없습니다.

통신 명령: HELLO, PING, STATUS, ARM, DISARM, STOP, POSE,base,shoulder,elbow,grip, AXIS,axis,angle (axis는 0~3, angle은 정수 0~180이고 펌웨어에서 제한 각도를 다시 검사).
펌웨어는 제어 잠금으로 시작하며, 명령 허용 후 1°/25ms로 천천히 움직이고, 약 3.5초간 통신이 없으면 출력을 끄고 잠금 상태로 전환합니다. STOP은 서보 PWM을 비활성화하지만 팔이 처질 수 있으며, **비상 전원 차단 장치를 대신하지 않습니다**.

## 3. 실물 자동 집기 보정 순서

1. 먼저 웹의 **시뮬레이터**에서 명령 흐름과 작업대 표식을 확인합니다.
2. 실물 모드 전환 → **USB 연결** → 실물 주변 안전 확인 → **실물 제어 허용**을 누릅니다.
3. 각 관절을 한 축씩 무부하로 움직여 동작 범위와 기계적 간섭을 확인합니다.
4. 웹의 보정 패널에서 HOME, HOVER_A, PICK_A, HOVER_B, PICK_B, HOVER_C, PICK_C, HOVER_BIN, PLACE_BIN **아홉 자세**를 각각 확인합니다. 반드시 **관절 각도 전송**을 눌러 실제 모터가 해당 자세로 이동한 것을 현장에서 확인한 후, **현재 각도 저장**을 누르세요. 웹앱은 실제로 전송·완료된 각도만 보정값으로 저장하도록 제한합니다. **아홉 자세를 보정하기 전 자동 집기는 차단됩니다.**
5. ‘집게 열림’과 ‘집게 닫힘’ 각도를 실제 물체와 서보 방향에 맞게 확인합니다. 초기 숫자는 예시입니다.
6. 카메라 또는 눈으로 A·B·C 물체의 위치를 확인하고 **직접 확인**을 체크합니다.
7. 채팅으로 대상과 목적지를 해석한 뒤, 실행 후보를 확인하고 다시 사람 승인을 받습니다.
8. 실행 명령은 Arduino에 전송되고 단계마다 응답을 기다립니다. **DONE POSE는 모터 명령 완료이며 실제 집기 성공의 증거가 아닙니다.** 반드시 실제 물체가 보관함에 옮겨졌는지 관찰하세요.

실물 집기 대상은 A·B·C의 **사전에 보정한 고정 위치**입니다. 현재 구현은 임의 위치 물체의 깊이/3차원 좌표를 계산하거나 자유롭게 팔을 이동시키지 않습니다.

## 4. 카메라·사진 인식 연결

기본 상태에서는 A/B/C 물체를 사람이 선택합니다. 이 모드는 **수동 확인**으로 표시되며 AI 예측이라고 주장하지 않습니다.

1. Google Teachable Machine 이미지 프로젝트에서 circle, triangle, cross 또는 원, 삼각형, 십자 3개 클래스를 만들고 사진을 수집해 학습합니다.
2. 모델을 HTTPS URL로 공유합니다. 웹의 ‘학습된 이미지 모델 URL’에 넣고 불러옵니다.
3. 카메라를 고정하고 영상의 왼쪽 1/3에 A, 가운데 1/3에 B, 오른쪽 1/3에 C가 보이게 합니다.
4. ‘A·B·C 사진 분류’를 누르면 각 영역의 표식을 예측합니다. 최고 점수 80% 미만이거나 알 수 없는 클래스는 보류합니다.
5. 화면의 결과와 실제 물체·자리 이름을 비교하고 사람이 승인합니다.

**제한:** 현재 카메라 화면의 3등분은 편의용이며 카메라 보정이나 3D 위치 추정이 아닙니다. 동적인 위치 추적, 작업대 인식, 물리적인 그립 성공 판정은 구현되지 않았습니다.

## 5. 수업·학생 평가에 활용할 증거

| 학습 활동 | 학생의 판단 | 자료 |
|---|---|---|
| 데이터 수집·정제 | 흐린 사진과 잘못된 라벨을 고칠까? | 사진 정제 기록 |
| 이미지 AI 검증 | 실제 표식과 예측이 왜 다른가? | 오분류 사례 |
| 한국어 명령 | “아무거나 집어 줘”를 실행해도 되는가? | 승인·보류 이유 |
| 기계 설계 | 인식이 맞는데 집기 중 놓친 이유는? | 집게 폭·접촉면 측정 기록 |
| 전후 실험 | 패드를 한 요소만 바꾼 것이 영향을 주었는가? | CAD 파일·동일 조건 반복 기록 |

**2027학년도 학생 적용 예정입니다.** 현재 실물 집기 성공률이나 학습 효과를 측정했다는 의미가 아닙니다.

## 6. 실물 구동 전 체크

- [ ] 서보 외부 전원, 극성, 허용 전류, 공통 GND 확인
- [ ] 적정 굵기의 전원 배선·퓨즈 및 물리적 전원 차단 장치 설치
- [ ] 링크/관절의 처짐 방지 지지대와 안전 작업구역 확인
- [ ] 서보별 PWM 폭, 방향, 기계적 제한 각도, 시작 자세 점검
- [ ] 하나의 관절만 저속으로 움직이고 STOP 및 통신 두절 확인
- [ ] 9개 위치 실물 보정 완료
- [ ] 사람의 표식 검증 및 실행 승인
- [ ] Arduino 출력 완료와 실제 물체 이동 결과를 따로 기록
